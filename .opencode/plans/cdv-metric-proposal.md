## 二、上手速度指标设计

### 2.1 核心概念

在七圣召唤中，卡组的"上手速度"指的是特定组件（一张或多张卡的组合）从牌库进入手牌的速度。这直接影响：
- **一致性**: 关键组合多久能凑齐？
- **节奏**: 第几回合可以执行核心计划？
- **容错**: 依赖组件的卡组有多可靠？

### 2.2 基础模型

**游戏参数**:
- 牌库大小: N = 30
- 起手: d₀ = 5 张
- 每回合摸牌: Δ = 2 张
- 第 r 回合结束时总摸牌数: d(r) = 5 + 2r
- Mulligan: 可自由替换手牌（首次替换无惩罚）
- Legend牌: 保证在起手中

### 2.3 指标定义

#### 指标1: CDV_p — 组件上手概率曲线

**CDV(C, r)** = P(在回合 r 结束时，手牌中包含组件 C 所需的所有牌)

- C 是一个命名组件，定义为一组 (卡牌名, 所需张数) 对
- 使用超几何分布精确计算（单卡）或多变量超几何分布（多卡组合）

**示例**: CDV(宵宫天赋, 3) = 60.7% 表示在第3回合末有60.7%概率手中有至少1张天赋

#### 指标2: HLR_p — 半值回合数 (核心标量指标)

**HLR_p(C)** = min{r ∈ ℕ : CDV(C, r) ≥ p}

即概率首次达到阈值的回合数。

| p 值 | 含义 |
|------|------|
| p=0.50 | **中位数回合** — 50%对局中此组件已上手 |
| p=0.75 | **可靠回合** — 3/4对局中已上手 |
| p=0.90 | **高置信回合** — 90%对局中已上手 |

**HLR 越低越好**，表示组件越早上手。

#### 指标3: WAS — 加权上手速度 (综合标量)

**WAS(C)** = 0.4 × CDV(C, 0) + 0.3 × CDV(C, 3) + 0.2 × CDV(C, 5) + 0.1 × CDV(C, 7)

- 权重强调前期（r=0 起手权重最大），因为七圣召唤节奏快
- WAS ∈ [0, 1]，越接近1表示组件越早上手
- WAS = 1.0 意味着起手必上手（如Legend牌）
- WAS < 0.3 表示组件严重依赖后期摸牌

#### 指标4: E-WAS — 考虑过牌加速的有效上手速度

考虑卡组内过牌效果的加速因子。如果卡组有效过牌加速比为 α（α > 1 表示比标准摸牌更快）：

**E-WAS(C, α)** = 0.4 × CDV(C, 0) + 0.3 × CDV'(C, 3) + 0.2 × CDV'(C, 5) + 0.1 × CDV'(C, 7)

其中 CDV'(C, r) 使用调整后的摸牌数 d'(r) = 5 + 2αr

#### α 的推导方法

α 不应是纯经验估计，应有明确的计算方法。推荐方案：

**α = 1 + (E[额外摸牌数] / E[标准摸牌数])**

其中标准摸牌数为每回合2张，额外摸牌数基于卡组过牌卡在预期对局长度内的期望产出。

具体步骤：
1. 计算卡组总过牌量：对每张过牌卡，根据其触发条件估算期望过牌数
   - 即时过牌（如运筹帷幝 +2）：期望 ≈ 2 × 上手率
   - 持续过牌（如浮溯之珏 +1/round）：期望 ≈ min(avg_game_rounds, 上手率) × 每回合产出
   - 爆发过牌（如常九爷 +2 burst）：期望 ≈ 2 × 上手率 × 触发率
2. 对局长度假设：取 L 回合（建议 L=6~8 作为典型值）
3. 计算：`总额外期望摸牌数 / (2 × L)` 即为 α 的增量

**本卡组示例** (取 L=7):
- 运筹帷幝 ×2：每张期望 ≈ 2 × CDV(r≈3) ≈ 2 × 0.607 × 2 = 2.43
- 浮溯之珏 ×2：每张期望 ≈ min(4, 上手率) × 1/round ≈ 0.76 × 3 ≈ 2.28 (假设平均触发3回合)
- 常九爷 ×2：每张期望 ≈ 2 × 上手率 × 触发率 ≈ 2 × 0.55 × 0.7 ≈ 1.54
- 寻宝仙灵 ×2：每张期望 ≈ 3 × 上手率 × 触发率 ≈ 3 × 0.55 × 0.6 ≈ 0.99
- 卯师傅 ×2：每张期望 ≈ 1 × 上手率 × 触发率 ≈ 0.55 × 0.8 ≈ 0.44
- 总额外期望 ≈ 7.68 ≈ 8 张
- α ≈ 1 + 8 / (2 × 7) = 1 + 0.57 ≈ **1.57**

原先的 α ≈ 1.25~1.5 范围偏保守，更精确的估算约为 1.5~1.6。注意 α 的取值对 E-WAS 结果影响显著，建议在实施时支持自定义 α 值。

### 2.4 计算公式

#### 单卡 (k 张复制品在30张牌库中)

P(摸到 ≥1 张 | 已摸 d 张) = 1 - C(30-k, d) / C(30, d)

#### 双卡组件 (需要卡牌A(k₁张)≥1 AND 卡牌B(k₂张)≥1)

P = 1 - P(0A) - P(0B) + P(0A ∧ 0B)

其中:
- P(0A) = C(30-k₁, d) / C(30, d)
- P(0A ∧ 0B) = C(30-k₁-k₂, d) / C(30, d)

#### 替代卡池 (需要卡牌A(k₁张)≥1 OR 卡牌B(k₂张)≥1)

P = P(≥1A) + P(≥1B) - P(≥1A ∧ ≥1B) = 2×P(≥1) - P(同时有)

当 k₁ = k₂ 时简化。

#### 三卡及以上: Monte Carlo 模拟或使用多变量超几何分布精确计算

## 四、Mulligan 优化对 CDV 的影响

在七圣召唤中，起手替换(mulligan)可以主动替换不需要的牌来搜索关键牌。这对 CDV 的影响：

**七圣召唤换牌黑名单机制** ⚠️:

七圣召唤的换牌（switchHands）比一般TCG的mulligan更加严格。源码见 `packages/core/src/mutator.ts:1227-1295`：

1. 被换下的牌放回牌堆（随机位置插入）
2. 从牌堆顶摸取等量新牌，但**跳过所有与被换下牌同名（同definition.id）的卡**
3. 即：如果你换下了一张"赌徒的耳环"，那么牌堆中**另一张**"赌徒的耳环也会被跳过，不会作为替换牌被摸上来
4. 仅当牌堆中所有牌都是黑名单中的同名卡时，才不再跳过（fallback至牌堆的首张牌）

**数学建模**:

设换出 k 张手牌，这些卡的 distinct 名字集合为 S。对于名字 s ∈ S，设牌库中共有 n_s 张同名卡，手中未换出的同名卡张数为 t_s。

步骤：
1. 换出的 k 张牌放回牌堆，牌堆变为 25 + k 张
2. 黑名单排除牌堆中所有名字在 S 中的卡：共 ∑_{s∈S}(n_s - t_s) 张
3. 有效摸牌池大小：N_eff = 25 + k - ∑_{s∈S}(n_s - t_s)
4. 从 N_eff 张非黑名单牌中无放回地摸 k 张

**常见简化场景**: 全换（k=5），每张换出的牌在牌库中恰好各有2张同名卡：
- S 包含 5 个名字，每个 n_s = 2，t_s = 0（全换出后手中无保留的同名卡）
- 更常见：S 中有些名字仅有 1 张（如Legend牌不参与换牌），有些有 2 张
- 对于本卡组典型场景（换出5张，其中4张有2副本、1张有1副本）：
  - 黑名单卡数 = ∑(2-0)×4 + (1-0)×1 = 9（5张换出 + 4张牌堆中的同名副本）
  - N_eff = 25 + 5 - 9 = 21

**含 Mulligan 的修正公式**:

对于搜索单卡（目标卡有 c_total 张在30张牌库中）:
- 起手5张看到概率: P₀ = 1 - C(30-c_total, 5) / C(30, 5)
- 若未看到（概率 1-P₀），假设全换5张后从 N_eff 张有效池中摸5张:
  P₁ = 1 - C(N_eff - c_remaining, 5) / C(N_eff, 5)
  其中 c_remaining 为目标卡在有效池中的张数（= c_total，因为目标卡不在黑名单中）
- 含Mulligan的总概率: P = P₀ + (1 - P₀) × P₁

**实际计算**: 全换5张的场景下（N_eff ≈ 21，目标2副本卡）：
- P₀ = 1 - C(28,5)/C(30,5) = 1 - 98280/142506 ≈ 31.0%
- P₁ = 1 - C(19,5)/C(21,5) = 1 - 11628/20349 ≈ 42.8%（注意分母从25变为21，分子从23变为19）
- P = 0.310 + 0.690 × 0.428 ≈ **60.5%**

对比不注意黑名单时的错误计算（从25张池中摸5张）：
- P₁' = 1 - C(23,5)/C(25,5) = 1 - 33649/53130 ≈ 36.7%
- P' = 0.310 + 0.690 × 0.367 ≈ 56.3%

**黑名单机制使mulligan实际上更强**：有效池从25缩减为约21，但目标卡密度从2/25提升到2/21，摸到概率从36.7%提升至42.8%。全换后总上手概率从估算的45%~55%修正为约**60%**。

**优化替换策略**:
1. 起手看5张，替换所有非关键牌来搜索核心组件
2. 由于黑名单机制，换出某张卡的同时也排除了牌堆中其同名卡，使得目标卡在有效池中的浓度更高
3. 但也意味着：如果你保留了一张卡（如浮溯之珏），换出其他4张时无法摸到浮溯之珏的第二张——因为浮溯之珏不在黑名单中但它的副本密度在有效池中被稀释

## 五、指标通用性设计

### 5.1 通用 CDV 计算框架

```typescript
interface Component {
  name: string
  requirements: CardRequirement[]  // 需要的卡牌及其数量
  alternatives?: CardRequirement[][]  // 替代方案（满足任一组即可）
}

interface CardRequirement {
  cardIds: number[]  // 可以是同一张的不同ID（如替代卡池）
  count: number      // 需要的张数
}

// CDV 计算
function calcCDV(component: Component, deckSize: number, round: number, drawPerRound: number): number

// HLR 计算
function calcHLR(component: Component, deckSize: number, drawPerRound: number, threshold: number): number

// WAS 计算
function calcWAS(component: Component, deckSize: number, drawPerRound: number): number
```

### 5.2 与现有 V2 特征的集成

CDV/WAS 可以作为 `DeckFeaturesV2` 的补充特征：

```typescript
// 新增到 sparse 特征中
{
  key: "deck.draw_velocity.component_X_hlr50",
  value: 2,  // 半值回合数
  source: "rule"
}
{
  key: "deck.draw_velocity.deck_was",
  value: 0.526,
  source: "rule"
}
```

### 5.3 Legend牌特殊处理

Legend牌（如磐岩盟契）保证在起手5张中出现，因此:
- CDV(Legend, r) = 1.0 对所有 r ≥ 0
- HLR_p(Legend) = 0 对所有 p
- WAS(Legend) = 1.0

## 六、本卡组诊断解读

### 优势
1. **0费圣遗物上手极快** (WAS=0.762, HLR₅₀=r0): 赌徒耳环/浮溯之珏有4张有效复品，起手即可上手
2. **Legend保证**: 磐岩盟契100%上手，0骰应急
3. **多种过牌手段**: 运筹帷幄、卯师傅、常九爷、寻宝仙灵提供了18点card_draw功能标签

### 瓶颈
1. **天赋上手中等偏慢** (WAS=0.545, HLR₅₀=r2): 2张天赋需要到第2回合才50%上手，carry节奏可能被拖慢
2. **双卡组合一致性低** (WAS=0.329): 卯师傅+常九爷同时上手的概率在第5回合才56.7%，依赖摸牌
3. **完整carry启动链缓慢** (天赋+圣遗物: WAS=0.442): 三卡组合(HLR₅₀=r5)意味着carry完全成型要到中期

### 改进建议
- 提高关键卡张数或增加替代卡池可提升WAS约0.1~0.2
- 运营型卡组的WAS=0.526属中等，核心carry组件的WAS偏低(0.442)是主要风险
- 可通过Mulligan优化将天赋起手率从31%提升至~50%，显著改善HLR₅₀
