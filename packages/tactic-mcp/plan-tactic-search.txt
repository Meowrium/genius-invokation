这份计划书旨在构建一个基于**符号AI与规则引擎**的“七圣召唤组合博弈挖掘系统”。该系统将作为AI训练的前置模块，提供高可解释性的战术指导。
---
# 七圣召唤AI：组合博弈挖掘与专家系统开发计划书
## 1. 项目概述
### 1.1 项目背景
七圣召唤是一款具有高随机性、非线性收益特征的回合制卡牌游戏。传统的纯数据驱动AI模型在少量样本下难以区分“运气成分”与“技术趋势”，且容易受非线性数值涨落的影响。
### 1.2 核心目标
构建一套**不依赖大规模训练**的专家规则系统，通过枚举与图搜索算法，挖掘卡牌与技能间的高收益组合链条。
该系统需具备以下能力：
*   **组合挖掘**：自动发现跨角色、跨回合的高收益Combo。
*   **风险评估**：准确区分“快速行动”与“战斗行动”带来的节奏风险。
*   **可解释性**：输出自然语言形式的战术分析报告，而非黑盒数值。
---
## 2. 核心理论框架
本系统采用**“状态机搜索 + 风险折损模型”**架构，将卡牌博弈转化为路径寻优问题。
### 2.1 技能原子化
将所有技能、卡牌抽象为**状态转换器**。
*   **输入**：骰子费用、前置条件（如元素附着、充能状态）。
*   **输出**：伤害数值、元素附着、资源获取（充能/手牌）。
*   **标签**：`Quick_Action`（快速）、`Combat_Action`（战斗）、`Reaction_Trigger`（反应触发）。
### 2.2 收益评估模型
引入**“期望收益 = 理论收益 × 完成率系数”**公式。
*   **理论收益**：基础伤害 + 反应倍率 + 资源价值。
*   **完成率系数**：基于行动类型（快速/战斗）与斩杀线的动态系数。
---
## 3. 模块化设计方案
### 模块一：数据结构化与标签系统
**功能**：将游戏数据转化为代码可读的结构。
**实施方案**：
1.  **构建标签库**：定义`Pyro_Apply`（挂火）、`Energy_Gain`（充能）、`Switch_Save`（切人防御）等标准标签。
2.  **技能映射**：
    ```python
    Skill_Data = {
        "id": "Diluc_E",
        "type": "Combat_Action",
        "cost": {"Pyro": 3},
        "outputs": ["Pyro_Apply", "Damage_3"],
        "needs": []
    }
    ```
3.  **反应规则表**：硬编码元素反应逻辑（如：火+水=蒸发，倍率2.0）。
### 模块二：组合链路枚举引擎
**功能**：搜索从起手到结束的高收益路径。
**实施方案**：
1.  **图构建**：以“当前场面状态”为节点，以“技能/卡牌”为边。
2.  **DFS搜索算法**：
    *   从当前状态出发，递归遍历所有可用技能。
    *   记录路径上的“元素残留”与“资源消耗”。
    *   当资源耗尽或触发关键反应时，终止该分支并记录路径。
3.  **剪枝策略**：忽略明显亏损的路径（如无意义元素附着、低伤高费操作）。
### 模块三：节奏与风险量化
**功能**：解决“战斗行动打断连招”的评估难题。
**实施方案**：
1.  **中断检测**：若链条中存在`Combat_Action`且后续依赖前置状态，标记为`Interrupted`（中断）。
2.  **系数修正**：
    *   **快速行动链条**：系数 = 1.0（收益稳定）。
    *   **战斗行动链条（未斩杀）**：系数 = 0.5~0.7（对手有应对窗口）。
    *   **战斗行动链条（已斩杀）**：系数 = 1.0（对手无法响应）。
3.  **风险输出**：标记链条中的“风险节点”，如“此处切换角色可能导致挂元素失败”。
### 模块四：可解释性输出接口
**功能**：生成人类可读的战术报告。
**实施方案**：
1.  **模板化生成**：基于路径节点，拼接自然语言描述。
2.  **报告结构**：
    *   **组合名称**：（如“蒸发斩杀轴”）。
    *   **操作序列**：A技能 -> B卡牌 -> C技能。
    *   **收益分析**：理论伤害 vs 实际期望伤害。
    *   **风险提示**：是否存在被反制的可能。

## 4. 开发实施路线图
### 第一阶段：基建构建（Week 1-2）
*   **任务**：完成全角色技能、卡牌数据的录入与标签化。
*   **交付**：标准化的JSON数据库，包含所有元素反应规则定义。
### 第二阶段：算法实现（Week 3-4）
*   **任务**：编写DFS路径搜索算法，实现基础的单回合Combo枚举。
*   **重点**：验证“伤害计算”与“元素附着逻辑”的正确性。
### 第三阶段：风险模型集成（Week 5）
*   **任务**：植入“快速/战斗行动”判定逻辑，加入斩杀线检测。
*   **交付**：能够输出带风险评级的Combo列表。
### 第四阶段：AI接口封装（Week 6）
*   **任务**：将系统封装为API，供AI模型调用。
*   **功能**：AI输入当前场面，系统返回Top-K推荐操作及解释。

## 5. 预期成果示例
**系统输入**：
> 当前手牌：[交给我吧]、[ tamb]...
> 场面：敌冻结状态（水附着），我方前台迪卢克（充能满），后台行秋。
**系统输出**：
> **【推荐组合 #1：斩杀确认】**
> *   **操作链**：使用[交给我吧](快速切人行秋) -> 行秋Q(快速挂水) -> 迪卢克Q(战斗，融化爆发)。
> *   **伤害预期**：12点（融化）+ 2点（行秋），共14点。
> *   **风险评估**：**低风险**。因使用了快速行动切人，对手无反应时间，且迪卢克大招为终结技，收益最大化。
>
> **【推荐组合 #2：常规压制】**
> *   **操作链**：迪卢克E(战斗) -> 迪卢克E(战斗)。
> *   **风险提示**：**中风险**。连续战斗行动未触发反应，且未利用冻结状态，收益较低。
---
## 6. 总结
本计划书旨在通过**符号推理**弥补纯深度学习在少量数据下的不足。通过显式地编码规则、枚举组合、量化风险，我们能够构建一个既懂“算数”又懂“博弈”的专家系统。这不仅能为AI提供高质量的训练样本（加速收敛），也能为人类玩家提供深度的战术分析。
